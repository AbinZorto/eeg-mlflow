\multicolumn{2}{l}{\textbf{Training strategy and batch sizing}} \\
\addlinespace
Training regime & Full-batch gradient descent per LOPO fold. The batch-size ceiling of 8192 is a guard value, not a tuned hyperparameter: it was set to exceed the largest per-fold dataset in the sweep ($\approx$ 5,000 windows at 2~s) and is automatically reduced to the training-set size by the batch-resolution logic (effective batch $\approx$ 2,300 windows at 6~s). Full-batch was chosen deliberately because the architecture contains BatchNorm1d layers after every convolutional block; with per-fold datasets of only 2,000--5,000 windows, conventional mini-batch sizes (32--128) would produce high-variance normalization statistics that could encode participant identity rather than population-level features. Full-batch accumulation yields stable, reproducible statistics from the entire training fold and is tractable because each LOPO fold is trained independently on a single GPU. \\
